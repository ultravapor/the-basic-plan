# 구현 요약 — 2026-09-17 (MVO: 병원 유입·전환 점검)

기준 문서: [master-strategy.md](master-strategy.md). 목표는 사이트 완성이 아니라,
`병원 유입·전환 점검`을 판매·검증할 수 있는 실험 가능한 상태를 만드는 것.

## 구현한 것
- **마스터 전략 문서화**: `docs/master-strategy.md`(최상위 기준), `diagnostic-sop.md`,
  `diagnostic-report-template.md`, `diagnostic-intake.md`(신청 필드 명세).
- **점검 페이지 보강**(`/checkup/`, 이미 존재하던 페이지에 추가):
  - 단계별 대표 병목 그리드(발견~예약).
  - 결과 정리 예시에 "예시 — 실제 고객 사례 아님" 라벨.
  - "진단 결과, 이런 결론도 가능합니다" 목록(대행사 유지/블로그 안 늘려도 됨 등).
  - 진단 퍼널 이벤트 추적: `diagnostic_page_view`, `diagnostic_cta_click`(Vercel Analytics).
- **콘텐츠 메타데이터 구조**(내부·비노출): `content.config.ts`에 `funnel`(P1~P5),
  `doubt`(H1~H6), `hypothesis`(자유 태그) 추가. 2편 시범 태깅.
- **카피 개선**: 홈·About의 추상 표현("데이터 기반의 방향", "이기는 전략")을 관찰 가능한
  행동으로. About에 "무엇을 하고 무엇을 하지 않는가"(대표·AI·외주 역할, 확실/실험 구분) 신설.
  About CTA를 `/checkup/`로. 콘텐츠 절대표현("유일한 길") 1건 완화.

## 아직 구현하지 않은 것
- 온사이트 신청 폼(다필드): 현재는 네이버 폼 링크 유지. 확장하려면 Formspree 등 엔드포인트 필요.
- 전 게시글 메타데이터 태깅(22편 중 2편만 시범).
- article_view / related_article_click 등 콘텐츠 단위 이벤트(점검 이벤트만 우선 적용).
- 정보구조(IA) 전면 재편 — 현재 구조가 유효해 무리하게 바꾸지 않음.

## 전략적으로 보류한 것
- 완성형 월정액 상품 정의(원칙상 지금 고정하지 않음).
- 1차 소스(집계 데이터) 페이지 — 대표의 실제 진단 숫자가 쌓인 뒤 제작.

## 추가로 필요한 데이터
- 네이버 폼에 인테이크 필드 반영 여부(또는 Formspree ID).
- 첫 점검 사례의 실제 수치(보고서 템플릿·1차 소스화의 재료).

## 다음 3개 우선순위
1. 신청 폼을 인테이크 필드로 확장(네이버 폼 수정 또는 온사이트 폼).
2. 5단계(검증) 글 "지금 돈 쓸 필요 없는 병원" 발행 — 점검 페이지로 유입.
3. 첫 점검 1건 실행 → 보고서 템플릿 검증 → 익명 집계로 1차 소스 착수.
