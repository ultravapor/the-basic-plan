# 페이지 제작 워크플로 (SOP)

> 대표가 "○○ 페이지 만들어줘"라고 하면, Claude가 이 순서대로 진행한다.
> 목적: 매번 다르게 하지 않고 **일관된 단계·승인 지점**으로 페이지를 만든다.
> 상위 기준: [master-strategy.md](master-strategy.md) · [content-planning-rules.md](content-planning-rules.md) · [content-writing-template.md](content-writing-template.md).
> 핵심 원칙은 그대로 적용: 추상어→관찰가능 행동, 볼드(**) 남발·AI 티 금지, 보장·근거 없는 숫자 금지, 한 문장 한 줄.

---

## 이 문서를 읽는 법 (한눈에)

페이지 제작은 **6단계**이고, 각 단계 사이에 **대표의 승인(🚦 게이트)** 이 있다.
승인 없이 다음 단계로 넘어가지 않는다. "코딩 → 보여주기 → 승인 → 코딩"의 반복이다.

```
0. 요청 접수      → Claude가 질문, 대표가 자료 제공
   🚦 게이트 A: 기획안 승인
1. 기획안 작성    → Claude가 구조·카피 방향 제시 (코딩 전)
   🚦 게이트 B: "이 구조로 ㄱㄱ"
2. 1차 코딩(초안) → Claude가 만들고 프리뷰로 보여줌
   🚦 게이트 C: 피드백 / 수정 요청
3. 수정 루프      → 피드백 → 코딩 → 프리뷰 (반복)
   🚦 게이트 D: 최종 승인 ("발행해도 돼")
4. 발행 전 QA     → Claude가 체크리스트 자동 점검
5. 발행 & 검증    → push → 라이브 200 → indexnow
   (측정은 14일 뒤 재확인)
```

> **page냐 post냐 먼저 구분한다.**
> - **글(post)** = 인사이트/정보 글 → `src/content/posts/*.md` (마크다운만, 예약 큐 대상). 이건 이 문서가 아니라 [content-writing-template.md](content-writing-template.md) 따른다.
> - **페이지(page)** = 랜딩/도구/실사실 같은 구조물 → `src/pages/*.astro` (디자인·레이아웃 있음). **이 문서는 페이지(.astro) 제작용이다.**

---

## 0단계 — 요청 접수 (Claude가 묻고, 대표가 답한다)

대표가 페이지를 요청하면, Claude는 **아래를 먼저 묻는다.** 이미 대화에 있으면 다시 묻지 않는다.

**Claude가 확인할 것 (없으면 질문):**
1. **목적 한 줄** — 이 페이지는 무엇을 하게 만드는가? (예: MVO 신청 / 가이드 다운로드 / 판매자 신뢰 / 발견용)
2. **타겟** — 누가 보는가? (기본값: ICP = 이미 돈 쓰는 비급여 원장. 다르면 명시)
3. **퍼널 위치** — P1 발견 / P2 비교 / P3 문의 / P4 응대 / P5 예약 중 어디?
4. **제거할 의심** — H1 해결책 / H2 상품 / H3 판매자 / H4 증거 / H5 자기판단 / H6 구매후 중 무엇?
5. **원하는 다음 행동(CTA)** — 이 페이지를 본 뒤 대표가 바라는 한 가지 행동.
6. **색인 여부** — 검색에 노출할 페이지인가, 아니면 **광고 랜딩이라 noindex**인가? (광고 전용은 `/diagnosis/`처럼 noindex + 사이트맵 제외)
7. **URL** — 원하는 주소. (예: `/checkup/`) 없으면 Claude가 제안.

**대표가 줄 자료 (있으면 다 주세요 — 많을수록 정확):**
- 참고 카피/문구 (직접 쓴 초안, 전자책, 기존 글)
- 참고 디자인 (좋아하는 경쟁사/사이트 링크나 스샷)
- 넣어야 할 실제 정보 (가격·절차·FAQ·연락 수단 등)
- 하지 말아야 할 것 (쓰기 싫은 표현, 피할 주장)

> 자료가 부족해도 괜찮다. Claude가 기획안으로 초안을 제시하고, 대표는 보면서 고치면 된다.
> **완벽한 설명을 미리 요구하지 않는다** — 보여주고 고치는 게 더 빠르다.

### 🚦 게이트 A → 1단계로
0단계 답이 모이면 Claude가 기획안을 쓴다.

---

## 1단계 — 기획안 작성 (코딩 전, Claude가 제시 → 대표 승인)

**아직 코딩하지 않는다.** Claude는 아래를 글로 제시한다 (표·목록으로, 1~2분에 읽히게):

1. **목적·타겟·퍼널·의심** (0단계 정리본)
2. **인식 변화** — old_belief → new_belief 한 줄 (이 페이지가 바꾸려는 믿음)
3. **섹션 구조(와이어프레임)** — 위에서 아래로 섹션 이름 + 각 섹션 한 줄 역할.
   예: `히어로(문제 공감) → 무엇을 받나(오퍼) → 절차 → 적합/부적합 → FAQ → CTA`
4. **카피 톤** — 어떤 말투로, 무엇을 강조/금지할지.
5. **CTA 동선** — 버튼이 어디로 가는가 (네이버 폼? /checkup/? 전화?).
6. **기술 메모** — JSON-LD 타입(Service/FAQPage/Article 등), 측정 이벤트(va), 색인/ noindex.

### 🚦 게이트 B
대표가 **"이 구조로 ㄱㄱ"** 또는 수정 지시. 승인 전엔 코딩 안 함.
구조가 크게 틀어지면 1단계를 다시 (코딩 전에 방향부터 맞춘다).

---

## 2단계 — 1차 코딩 (초안 제작 → 프리뷰로 보여주기)

승인된 기획안대로 Claude가 만든다:
1. `src/pages/<url>.astro` 작성 (기존 페이지 컴포넌트·스타일 패턴 재사용).
2. 필요 시 `src/consts.ts`(NAV 등), JSON-LD, 측정 이벤트 연결.
3. `npm run build` → 에러 0 확인.
4. `npm run check:seo` → 통과 확인.
5. **대표에게 보여주기** — 아래 중 하나로:
   - 로컬 프리뷰(`npm run dev`) 화면/스크린샷, 또는
   - 미리 push해서 라이브 URL로 확인 (대표가 폰에서도 보고 싶을 때)

> 이 단계 산출물은 "초안"이다. 완성이 아니다. 보여주는 게 목적.

### 🚦 게이트 C
대표가 보고 피드백. "여기 문구 바꿔 / 이 섹션 빼 / 색 바꿔" 등.

---

## 3단계 — 수정 루프 (피드백 → 코딩 → 프리뷰, 반복)

게이트 C의 피드백을 반영해 고치고 다시 보여준다. 만족할 때까지 반복.
- 한 번에 큰 덩어리씩 바꾸고, 바꾼 것만 짚어 보고한다 (before/after).
- 대표가 "이제 됐다 / 발행해도 돼"라고 하면 다음 단계.

### 🚦 게이트 D — 최종 발행 승인
대표의 명시적 승인("발행해")이 있어야 발행한다. (발행 = 외부 공개. 되돌리기 어려움)

---

## 4단계 — 발행 전 QA (Claude가 자동 점검, 통과 못 하면 발행 보류)

[content-writing-template.md](content-writing-template.md) 3절 QA + 페이지용 추가 점검:

- [ ] `npm run build` 에러 0 / `npm run check:seo` 통과
- [ ] 크롤러의 눈: 빌드된 HTML(JS 없이)에 h1·본문·메타·JSON-LD가 실제로 있는가
- [ ] 색인 의도 일치: 노출용은 `index`, 광고 랜딩은 `noindex` + 사이트맵 제외 확인
- [ ] JSON-LD가 화면 내용과 일치(거짓 구조화 데이터 금지), @id 그래프 일관
- [ ] CTA 링크가 실제 목적지로 감(네이버 폼 URL 등 깨짐 없음)
- [ ] 측정 이벤트(va) 연결 확인 — **이벤트 유실 함정 주의**([project-the-basic-plan-site] 메모)
- [ ] 추상어(데이터기반·맞춤형·파트너·책임감)를 관찰 가능한 행동으로 바꿨는가
- [ ] 근거 없는 숫자·절대어·매출 보장 없음 / 의료광고법 저촉 표현 없음
- [ ] 볼드(**) 남발·AI 티 없음, 한 문장 한 줄
- [ ] 모바일에서 레이아웃 깨짐 없음(대표가 폰 사용자)

---

## 5단계 — 발행 & 검증

표준 발행 워크플로:
```
git pull --ff-only
git add <파일>
git commit -m "..."   # author = ultravapor1228@gmail.com (Vercel Hobby 이메일 매칭)
git push              # push가 Vercel 배포를 트리거
# 라이브 200 확인 (배포 반영까지 보통 1~2분, 폴링)
node scripts/indexnow.mjs   # Bing·네이버·Yandex 즉시 제출 (Google은 사이트맵 자동크롤)
```
발행 후 필요 시: **NAV(상단 메뉴), llms.txt, 관련 글 내부링크**에 새 페이지 반영.

> 광고 랜딩(noindex)은 indexnow·사이트맵 제외 — 검색 노출이 목적이 아니므로.

### 보고 형식 (발행 후 대표에게)
① 만든 것(URL) ② 크롤러 눈 검증(라이브 200·핵심요소 확인) ③ 반영한 연결(NAV/llms/링크) ④ 다음 측정 일정.

## 6단계 — 측정 (고치고 끝이 아니다)

[fire-your-seo-agency 스킬 measure 원칙]: 발행 = 기준선. **14일 뒤 재측정**을 예약한다.
