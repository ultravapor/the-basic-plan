# 판단 포맷 — 글 쓰기 템플릿 (내부용)

> [master-strategy.md](master-strategy.md)의 PART 24·44·45·50을 매 글에 적용하기 위한 실무 체크판.
> 목적: 정보 나열이 아니라 **판단력이 눈에 보이는 글**을 일관되게 만든다(사고력 포트폴리오).
> 동일 템플릿을 기계적으로 강제하지는 않되, 아래를 기본값으로 삼는다.

## 0. 쓰기 전에 정의한다 (프론트매터/메모)
> 주제·순서·내부링크는 [content-planning-rules.md](content-planning-rules.md)를 먼저 적용한다.
- **인식 변화(필수)**: `old_belief`(읽기 전 믿음) → `new_belief`(읽은 뒤 새 판단). 글 하나 = 하나의 변화.
- **정체성 메시지(필수)**: `identity_message` — 이 관점을 받아들인 독자가 자신을 어떤 원장으로 느끼는가.
- **카테고리·팬 단계**: `category`(A~E) / `fanStage`(discovery~propagation).
- **이전/다음 사고단계 글**: `prevArticle` / `nextArticle`(slug) — 내부링크는 사고의 순서로.
- **검증하는 문제 가설**: 이 글은 어떤 Pain 가설을 시험하는가? (hypothesis 태그)
- **제거할 의심 하나**: H1 해결책 / H2 상품 / H3 판매자 / H4 증거 / H5 자기판단 / H6 구매후 (doubt 태그)
- **퍼널 위치**: P1 발견 / P2 관심·비교 / P3 문의 / P4 응대 / P5 예약 (funnel 태그)
- **읽기 전 살아 있는 반대 가설**: 독자가 지금 갖고 있는 "사지 않을 이유" 하나.
- **읽은 뒤 죽어야 할 반대 가설**: 위 가설이 어떤 증거·추론으로 사라지는가.
- **독자가 직접 확인할 방법**: 자기 병원에서 스스로 검증할 수 있는 한 가지.
- **예외/한계**: 이 설명이 틀릴 수 있는 조건.
- **다음 행동(CTA)**: 강한 판매가 아니라 자연스러운 점검 제안.

## 0-1. 검색어 적합성 — 제목·진입은 고객이 실제 치는 말로 (LLM/GEO/AEO 진입)
각도(관점)는 세계관에서 나오지만, **제목·첫 문장·핵심 키워드는 고객이 실제로 검색창에 치는 말**이어야 발견된다.
"내가 쓰고 싶은 말"이 아니라 "고객이 지금 당장 검색하는 말"인지 확인한다. (docs/content-planning-rules.md 8·11과 함께: 관점은 독특하게, 제목은 검색어로)

절차:
1. 누가 검색하는가(페르소나 좁히기) → 2. 그 사람의 상황 → 3. 실제로 할 법한 질문을 그대로 적기
→ 4. 질문을 검색어처럼 짧게(예: "세무사 비용 얼마지?" → "세무사 비용") → 5. 검색량·경쟁 감(신생 도메인은 롱테일 우선)
→ 6. 연관검색어/자동완성까지 봐서 추가 주제·부제로 → 7. 최종 확인: "내가 쓰고 싶은 말인가, 고객이 지금 치는 말인가?"

적용:
- **제목 = 검색어 + 예상 밖 결과 + 판단 기준**(PART 11). 예: "피부과 신환 안 늘 때" + "광고를 늘리기 전에 볼 것".
- `keywords[0]`을 이 글의 **주 타깃 검색어**로 둔다. `answer`/첫 문장에 그 말이 자연스럽게 들어가게.
- 연관검색어는 FAQ 질문이나 소제목으로 흡수(하나의 글이 여러 롱테일을 잡게).
- 도구: 네이버 자동완성·연관검색어는 브라우저로 확인 가능(정확한 검색량은 네이버 키워드도구=로그인 필요라 대략 감으로). 확인 안 된 수치는 본문에 단정하지 않는다.

## 0-2. 복잡성 축소 — 팩트의 해상도를 조절한다
전문가는 4K로 보지만 고객에게 4K를 들이밀 필요는 없다. 목표는 지식의 양이 아니라 **고객의 판단 비용을 줄이는 것**.
정보가 많아질수록 전문가는 정확해지지만 고객은 결정이 어려워진다. 그래서:
- **결론 먼저**(answer 한 줄) → 궁금해하면 그때 근거. 결론 없이 설명부터 시작하지 않는다.
- **100 중 지금 필요한 20만** 고른다. 떠오르는 예외 100개 중 이 결정에 중요한 **2~3개만**.
- 어려운 용어는 **고객 언어로 번역**(예: LLM → "ChatGPT처럼 답하는 AI"). 아는 걸 다 쓰지 않는다.
- "이건 신경 쓰지 않으셔도 됩니다", "선택지는 셋이지만 현실적으로는 두 번째" 처럼 **덜어내고 우선순위를 정해준다**.
- 단, **정확성은 포기하지 않는다.** 복잡함은 전문가 머릿속에 남기고, 고객에게는 해상도만 낮춘다.
  의료·법률처럼 오판 비용이 큰 영역은 특히(의료광고법 검증은 PART 18 유지).
- 좋은 글의 테스트: "정보를 더 줬는가"가 아니라 **"머릿속 질문 10개를 2개로, 선택지 2개를 우선순위 1개로 줄였는가."**

## 1. 본문 구조 기본값 (PART 45)
1. 독자가 지금 믿는 표면적 설명 — 예: "문의가 줄었으니 노출을 늘려야 한다."
2. 균열 — 예: "그런데 노출은 그대로인데 문의만 줄 수도 있다."
3. 대안 가설 — 예: "비교→문의 단계에서 이탈하고 있을 수 있다."
4. 판단 기준 — 무엇을 확인하면 되는지(경쟁사에도 적용 가능한 기준으로).
5. 직접 검증 — 독자가 자기 병원에서 확인하는 방법.
6. 예외와 한계 — 언제 이 설명이 틀리는가(반증 조건 공개).
7. 다음 행동 — 가벼운 점검 제안(`/checkup/`).

## 2. 세 역할 (최소 하나, 최고는 셋 동시 — PART 44)
- **문제 탐지 센서**: 어떤 Pain에 타깃이 실제로 반응하는지 본다.
- **반대 가설 제거 장치**: 구매를 막는 의심 하나를 제거한다.
- **사고력 포트폴리오**: 문제를 어떻게 구조화·판단하는지 보여준다(분해·구분·한계 명시가 핵심).

## 3. 발행 전 QA (통과 못 하면 발행하지 않는다)
- [ ] Q1: 읽기 전 존재하던 '사지 않을 이유' 하나가, 어떤 증거·추론 때문에 읽은 뒤 사라지는가? (답 못 하면 발행 금지)
- [ ] Q2: 읽은 사람이 "우리 말을 믿어서"가 아니라 **스스로 같은 결론에 도달**할 수 있는가? (후자가 더 좋음)
- [ ] 의심의 종류에 맞는 증거를 썼는가? (효과 의심에 대표 경력만 대지 않았는가)
- [ ] 추상어(데이터 기반·맞춤형·파트너·책임감·품질·철저함)를 관찰 가능한 행동으로 바꿨는가?
- [ ] 근거 없는 숫자·확률·절대어(반드시·무조건·유일한·N개 이상이면)를 쓰지 않았는가?
- [ ] 불리한 경우·예외·미검증 영역을 정직하게 밝혔는가?
- [ ] CTA가 앞단 설득 부족을 힘으로 밀어붙이지 않는가?
- [ ] 볼드(**) 남발·AI 티가 나지 않는가?

## 4. 하지 말 것 (PART 46)
우리 장점 나열 / "저희는 다릅니다" 중심 / 근거 없는 숫자·성공확률 / 모든 문제를 한 서비스로 설명 / AEO·GEO 공포 조장 / 무조건 매출 성장 약속 / 추상 감정 카피 / FOMO 중심 CTA / 경쟁사 비하 / 독자 대신 결론 내리기 / 성공 사례 하나를 보편화.
